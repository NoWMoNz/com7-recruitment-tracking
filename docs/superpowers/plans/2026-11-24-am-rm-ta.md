# AM / RM / TA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** This plan does four things:
- store each branch's AM and RM, filled from HR's Zone sheet
- let any TA hand a branch, and every not-closed position in it, to another TA
- add AM / RM / TA filters to Dashboard, tracking, manpower and Report
- show AM / RM / TA on manpower and in the Report's weekly tables

**Architecture:**
- `am`/`rm` are two new string columns on `Branches`.
- One small domain module (`people.ts`) holds the shared filter shape, the matcher, the dropdown options and the "TA of a branch" rule. Every page uses it.
- The TA hand-over is a pure planner (`branch-ta.ts`) plus a server action. It follows the existing `planRequisitionEdit` / `OwnerChange` pattern.

**Tech Stack:** Next.js 16 App Router (server components + server actions), TypeScript, Vitest, ExcelJS (import script), Google Sheets repo / in-memory repo.

**Spec:** `docs/superpowers/specs/2026-11-24-am-rm-ta-design.md`

## Global Constraints

- `Branches` columns: append `am`, `rm` (strings, empty = not set) after `close_date`.
- In Zone, `-` and blank mean empty. When an ID repeats, use the row that has names. Two different named rows for one ID: keep the first and add a warning.
- Change TA allowed for roles `ta` and `super_admin`, never `viewer`, only for branches in the viewer's scope (`inScope`).
- Statuses that move with the branch: `Vacancy`, `Offer`, `PendingCancel`, `PendingHold`, `Hold`.
- Log per moved requisition: `from_status` = current status, `to_status` = `"OwnerChange"`, note `` `เจ้าของ ${old} → ${new}: เปลี่ยน TA ประจำสาขา` `` (names via the Users tab, `ยังไม่มีเจ้าของ` for empty), `effective_date` = today (Bangkok), actor = viewer email.
- TA values in filters are normalized emails (`normalizeEmail`), and labels are user names. AM/RM values are the names as stored.
- Dropdown copy: `ทุก AM`, `ทุก RM`, `ทุก TA`. Missing name on screen: `-`.
- A monthly Report filtered by `am` or `rm` is computed live, never from a snapshot.
- No Excel column changes (part 4). Export routes must still honour the new filters so an export matches the screen.
- Do not commit. The user commits; each task's checkpoint is `pnpm test` green plus `npx tsc --noEmit -p .` clean.

## Review Focus

1. **Branch with no AM/RM** (136 real shops). It shows `-`, never appears as an empty dropdown option, and is excluded when an AM/RM filter is set. Tests: Task 2 (`peopleOptions` skips blanks) and Task 4.
2. **Moving a branch where some positions already belong to the new TA.** Those are neither patched nor logged. A change with nothing to move and an identical assignment returns `ไม่มีอะไรเปลี่ยน`. Test: Task 5.
3. **Someone edited one of the branch's positions meanwhile.** `updateMany` with versions throws ConflictError, and nothing is written: requisitions are written before assignments and log. Task 5 action order. The conflict itself is covered by the repo's existing tests.
4. **Email case** (`Mind@example.com` vs `mind@example.com`). It matches in filters, in "already owned", and in assignments. Tests: Task 2 and Task 5.
5. **Old Sheet without `am`/`rm` columns.** Pages render (values read as `""`), and the import file carries the columns. Covered by existing `rowsToObjects` behaviour. No new code.
